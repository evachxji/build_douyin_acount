# 需求分析

## 1. 产品定位

一个**本地运行、人机协作**的桌面工具，帮助短视频运营者完成：

```
海外平台采集 → 本地 AI 理解分析 → 人工挑选 → 文案生成 → 辅助发布到抖音
```

关键边界：

- 工具**不做无人值守发布**；账号登录、最终发布必须人工确认。
- 所有视频、分析结果、账号状态保存在**本机**。
- 采集与 AI 分析解耦，平台可插件化扩展。

## 2. 功能需求

### 2.1 视频采集模块

| 需求 | 说明 |
| --- | --- |
| 平台 | TikTok、Instagram Reels；架构上支持后续扩展 |
| 采集方式 | **刷平台默认推荐流**，不按关键词/账号/链接定向检索（用户补充约束） |
| 配额 | 每轮采集 **100 条**（可配置）：TikTok 30%（约 30 条）、Instagram 70%（约 70 条），平台比例可在设置中调整 |
| 过滤 | 点赞数 **> 1,000,000 的视频不采集**（上限可配置） |
| 保存字段 | 原始视频文件、标题、作者、来源链接、发布时间、标签、点赞/评论/播放数据（可获取时） |
| 输出 | 下载到本地并写入 SQLite，状态为 `NEW` |
| 要求 | 采集模块独立封装、平台适配器插件化、不依赖 AI 分析模块 |

### 2.2 AI 视频理解分析模块

对视频执行以下流水线：

```
视频 → 抽帧(FFmpeg) → Vision 模型分析关键帧 → Whisper ASR 转写音频 → LLM 综合判断
```

输出结构化 JSON：

```json
{
  "category": "宠物",
  "tags": ["猫", "治愈", "萌宠"],
  "quality_score": 85,
  "has_foreign_language": false,
  "has_large_amount_english_subtitle": false,
  "summary": "一只猫咪玩耍的视频",
  "recommended_caption": "..."
}
```

分类体系（初版）：

- 宠物：猫、狗、萌宠、搞笑
- 生活：日常、治愈、家庭
- 美食：做饭、探店、烘焙
- 手工：DIY、制作过程
- 风景：自然、城市、旅行

### 2.3 英文内容过滤

检测并标记不适合直接搬运到抖音的内容：

| 判定信号 | 手段 |
| --- | --- |
| 大段英文字幕 | OCR（Vision 模型 / 可选 PaddleOCR） |
| 英文对白占比高 | Whisper 转写 + 语言占比统计 |
| 主要面向海外受众 | LLM 综合判断 |

结果：`skip_download = true` 或进入低优先级列表（`LOW_PRIORITY`）。

### 2.4 本地视频管理系统

- SQLite 数据库，`VideoAsset` 表保存资产元数据。
- 状态机：`NEW → ANALYZING → READY → SELECTED → PUBLISHED`，另含 `SKIPPED / LOW_PRIORITY / DOWNLOAD_FAILED`。

### 2.5 PC 端管理界面

三栏布局：

- **左侧**：分类树（宠物/美食/手工/风景/生活/未分类，另含收藏、待发布等虚拟分类）
- **中间**：视频瀑布流（缩略图、标签、AI 评分、来源、状态徽章；多选、排序、筛选）
- **右侧**：详情面板（视频预览、元数据、AI 分析结果、推荐文案、操作按钮）

支持操作：播放、收藏、删除、标记发布、批量选择、生成文案。

### 2.6 AI 文案生成模块

- 输入：选中的视频 + 账号风格
- 输出：抖音标题、正文描述、话题标签
- 账号风格可配置：搞笑 / 治愈 / 高级感 / 情绪价值（可扩展）

### 2.7 抖音发布辅助

流程（**最终发布按钮绝不由程序点击**）：

```
用户选择视频 → 点击【准备发布】
  → 打开独立浏览器窗口 → 进入 creator.douyin.com
  → 自动填写：视频文件、标题、文案、标签
  → 停止，等待用户人工确认 → 用户本人点击【发布】
```

### 2.8 Agent 化架构

五个 Agent + 统一运行时：

| Agent | 职责 |
| --- | --- |
| Collector Agent | 视频发现、元数据采集、下载 |
| Vision Agent | 视频理解（抽帧、Vision、ASR、LLM 综合） |
| Filter Agent | 质量筛选、英文内容过滤 |
| Content Agent | 标题/文案/标签生成 |
| Publisher Assistant Agent | 辅助上传（人工确认节点） |

| Runtime 能力 | 说明 |
| --- | --- |
| 任务调度 | SQLite 持久化任务队列，支持恢复 |
| 状态管理 | Agent / 资产状态机 |
| 日志 | 结构化任务日志 |
| 重试 | 指数退避，可配置最大次数 |
| 人工审批节点 | 任务进入 `WAITING_FOR_HUMAN`，由用户在 GUI 确认 |

## 3. 用户补充约束（必须遵守）

1. **不检索**：只刷默认推荐流下载，不做关键词/账号主页定向检索。
2. **同名 GitHub 仓库**：仓库名 `build_douyin_acount`。
3. **独立浏览器窗口**：所有需要浏览器能力的脚本，不得在用户当前已打开的浏览器里新建标签，必须单独新开窗口（独立 Profile）。
4. **比例**：TikTok 30%、Instagram 70%（可配置）。
5. **上限**：点赞超过 100 万不采集（可配置）。
6. **批量**：每轮采集 100 条（可配置），AI 分类后，先由系统给出**每个标签下的推荐视频若干条**，再由用户勾选发布。

## 4. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 隐私 | 视频、Cookie、分析结果全部本地存储 |
| 可维护性 | 模块化、插件化、必要注释、不做一次性代码 |
| 稳定性 | 断点续采、任务可重试、失败可恢复 |
| 性能 | 本地 AI 单条分析控制在可接受时间（抽帧数量按视频时长动态） |
| 可扩展 | 新平台 = 新增一个 PlatformAdapter |
| 错误处理 | 不跳过错误处理；所有外部调用有超时与重试 |

## 5. 风险与对策

| 风险 | 对策 |
| --- | --- |
| TikTok / IG 反爬与风控 | 使用用户真实账号登录态（独立 Profile）；控制滚动/下载频率；失败退避 |
| 平台页面 DOM 变化 | 选择器集中管理（`resources/selectors/`）；优先走网络响应拦截而非 DOM |
| 视频版权 | 工具仅辅助运营者；删除按钮与版权提示 |
| 磁盘占用 | 每轮约 2~5GB；按需清理临时文件（抽帧、音频中间产物） |
| 本地模型性能 | 帧数自适应；ASR 用 small/base 模型；分析队列串行 |
| 抖音页面结构变化 | 发布辅助使用"可识别才操作"策略，识别失败即停止并提示人工 |
| 网络环境 | 所有外网请求走系统代理；超时与重试 |
